# Quality bars — Dodam (Baby Growth Book)

Ten metrics. Each is scored 0–100. **Launch gate: every metric ≥ 95.**
Machine parts are computed by `npm run qa` (`scripts/qa/run.mjs`); judged parts are scored against the
written rubric and the evidence is recorded in `docs/QUALITY_SCORECARD.md`.

| # | Metric | What it measures | How it is measured |
|---|--------|------------------|--------------------|
| 1 | **Information provenance** | Every milestone, play tip and watch-out names its source organisation, links to it, and quotes it. Sources are recognised child-development bodies (CDC, AAP/HealthyChildren, WHO, Zero to Three, NAEYC, CPSC, Pathways). A medical disclaimer is shown in onboarding, on every source card and in About. | Machine: 100% of items have `source`, `sourceUrl`, `sourceQuote`; URL host ∈ allow-list; each unique URL answers 200/3xx. Judged: 30-item sample checked against the source page. |
| 2 | **Information completeness & fit** | Months 1–36 are all covered: ≥6 milestones per month with ≥1 in each of the four categories, ≥3 play tips, ≥2 watch-outs, and a monthly parent note with all three voices. Content matches the month it is filed under. | Machine: coverage matrix. Judged: 1 month in every 6 read end-to-end for age fit. |
| 3 | **Bilingual parity & Korean naturalness** | English and Korean are the same book. Same IDs, months, categories, severities, difficulties, materials presence and URLs; every UI key exists in both languages; no English leaks into Korean UI; Korean uses one register (해요체) throughout; particles are correct after dynamic values. | Machine: structural parity 100%, key parity 100%, register scan (no 습니다/십시오/반말 endings), no Latin-only UI strings in `ko`, particle helper unit-tested. Judged: native-reader review of all UI strings, all 36 monthly notes, and ≥20% of items per file. |
| 4 | **Clarity & readability** | Parents can act on every sentence. English body text averages ≤ 22 words per sentence and Flesch Reading Ease ≥ 55; milestone titles ≤ 7 words (EN) / ≤ 18 characters (KO — one line at 15px beside the seal on a 390pt screen); every watch-out has an `action`. | Machine: all four computed. Judged: none. |
| 5 | **Visual identity & cohesion** | The chosen brand package is applied verbatim: the app paints only through brand tokens (light and dark), one display face plus the platform UI face, one ornament device, no emoji used as icons, semantic colour roles (done / danger / caution / info) are distinct and documented. | Machine: no raw hex / Tailwind palette colours in `src/` outside `globals.css`; no emoji code points in `src/`; every light token has a dark counterpart; icon set is a single library. Judged: side-by-side with the brand book. |
| 6 | **Minimal UX** | Nothing on screen that does not earn its place. Every core screen is ≤ 2 taps from Home; each screen has exactly one primary action; no navigation surface is duplicated; every screen has a way back; empty states say what to do next. | Machine: route-depth check in E2E, back-path check on every route. Judged: screen-by-screen audit against the rubric. |
| 7 | **Accessibility** | Usable by every parent, including with VoiceOver, larger text, reduced motion and dark mode. | Machine: axe-core (WCAG 2.1 AA) zero serious/critical violations on every route in light and dark; every token text pair ≥ 4.5:1 (body ≥ 7:1); every interactive element ≥ 44×44 CSS px; `prefers-reduced-motion` disables animation; `lang` attribute follows the chosen language; every control has an accessible name. |
| 8 | **Performance & offline** | Instant on a phone, works with no signal. | Machine: Lighthouse mobile Performance ≥ 95 on Home, Milestones, Play, Safety, Journal; first-load JS ≤ 250 kB gzipped per route; CLS < 0.02; the app shell and content load offline (E2E with network disabled). |
| 9 | **Reliability (zero known bugs)** | Nothing crashes, nothing loses data. | Machine: `tsc --strict` clean, ESLint clean, unit tests pass (age maths incl. leap day / month-end / future / >36 months, storage corruption tolerance, content integrity, i18n parity), E2E pass on iPhone and desktop viewports, zero console errors or warnings during E2E, data survives reload, 404 route renders. |
| 10 | **iOS & App Store readiness, privacy** | Ships as a native iOS app and passes review. | Machine: safe-area insets applied top and bottom; portrait-only; 1024×1024 opaque icon; splash; `ITSAppUsesNonExemptEncryption=NO`; privacy manifest present; privacy policy and terms routes live; runtime network calls limited to same-origin and font hosts; data export and delete exist; App Store metadata within limits (name ≤ 30, subtitle ≤ 30, keywords ≤ 100, description ≤ 4000) in EN and KO; screenshots at 1290×2796 and 1320×2868. Judged: review against App Store Review Guidelines 1.4.1 (health content), 4.2 (minimum functionality), 5.1.1 (privacy). |

## Scoring rule
- Machine checks: a metric starts at 100; each failing check deducts its weight (listed in `scripts/qa/run.mjs`).
- Judged checks: scored per rubric line, 0–100, averaged with the machine score at 50/50 where both exist.
- Anything below 95 blocks launch. The scorecard is regenerated before every release.
